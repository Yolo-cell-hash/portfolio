Most Indians already get a text for every bank transaction. The data to budget is already on the phone — yet popular apps still upload it, make you type it, or sell you a loan.

The problem

01 · What makes it different

Six decisions rivals didn't make.

The SMS-budgeting category was pioneered by apps that have since pivoted into lending. Budgetify competes on the ground they gave up: trust.

01

Privacy that's architectural, not a setting

Newer rivals advertise a “private mode” on apps that still have full network access, so you're asked to trust a toggle. Budgetify ships with no internet permission at all. It's technically incapable of uploading your data, and backups are AES-256 files that you keep.

02

Templates, not guesses

India's DLT rules make banks register their SMS templates. Known banks get anchored template packs; the generic parser is only a fallback, and its output is marked lower-confidence.

03

It admits when it isn't sure

Uncertain entries go to Tidy up: one card, three clear answers. Each correction teaches the parser, so the same message lands right next time.

04

Built for Indian money

Tax buckets for 80C, 80D, 24(b) and HRA that fill toward their caps and respect the old vs new regime. Self-transfers and investments stay out of spending.

05

Splits without sign-ups

An offline Splitwise-style ledger where the other people are just names. Settle up, then share a plain-text summary on WhatsApp.

06

A habit, not homework

Streaks with freezes, achievements, and a reward road that unlocks themes, royal avatars and matching launcher icons. Every month ends with a shareable Wrapped poster that hides the amounts unless you choose to reveal them.

07

Six languages, one layout

English, Hindi, Marathi, Bengali, Telugu and Tamil, with layouts that survive large text sizes in all of them.

02 · How I build it

A one-person team with a real process.

Shipping fast alone only works if every change is planned, reviewed, tested and reversible. This is the loop behind every release.

  1. Research before roadmap

    I mapped the Indian market — Axio, MoneyView, FinArt, Mera Kharcha and others — feature by feature, and ranked the gaps into tiers. Recurring payments came out on top, so it shipped next.

    Market analysis → ranked roadmap

  2. Write the plan first

    Every substantial feature starts as a written plan: why it exists, the data model, edge cases and what's deliberately out of scope. Recurring payments and tax buckets each had one before any code.

    Plan doc → pull request

  3. Pair with AI, review like a lead

    I build with Claude Code as a pair programmer, running features side by side in separate git worktrees. I set the direction, review every diff and own every merge.

    353 pull requests, each reviewed

  4. Two branches, never merged

    main is always shippable. dev-mode adds a tester's switchboard that unlocks every theme and reward. Fixes land on both by cherry-pick, so test tooling never leaks into a release.

    main + dev-mode, kept in step

  5. Test what users would notice

    Tests on the parser and the money maths, render tests on themes, and proof sheets that draw every theme at once. Bugs are ranked by what a user loses, not by how hard the fix is.

    125 test files · known-issues queue

  6. Ship small, explain every release

    Closed testing first, then the public listing. Small, frequent releases, each with localised “what's new” notes and a public changelog, and store listings tuned for each market.

    71 releases since January 2026

04 · Engineering notes

Small calls that build trust.

A money coach that stays quiet

Spending is heavily skewed, and one big purchase wrecks an average. Nudges use the median and median absolute deviation, so a lone outlier can't set off false alarms. An app that cries wolf gets uninstalled.

Removal that asks what you meant

“Not a transaction” mutes that message shape from that sender; “Just this one” removes a single entry. Both can be undone, and the undo survives an app restart.

Forecasts without a server

The opt-in prediction mode projects where the month will land at your current pace — computed on the phone from your own history, with no model call and nowhere for data to go.
